**ii. What is code optimization in a compiler?**
**Answer:** Code optimization is a phase of compilation where the compiler attempts to improve the intermediate code or target code so that the final program executes faster and/or consumes less memory, without altering its original meaning or output.

**iii. Discuss the advantages and limitations of code optimization techniques.**
**Answer:**
**Advantages:**
- **Performance Improvement:** The most significant advantage is faster execution speed of the compiled program.
- **Reduced Memory Usage:** Optimization can reduce the memory footprint of the program by eliminating dead code and optimizing variable storage.
- **Better Resource Utilization:** Makes efficient use of CPU registers, cache, and pipeline architectures.
- **Power Efficiency:** Faster execution and fewer memory accesses lead to lower power consumption, which is crucial for mobile and embedded devices.

**Limitations:**
- **Compilation Time:** Intensive optimization significantly increases the time it takes to compile the program.
- **Complexity:** Writing a good optimizer is highly complex and error-prone. Bugs in optimization can lead to incorrect program behavior that is very hard to debug.
- **Debugging Difficulty:** Optimized code often rearranges or eliminates variables and instructions, making it difficult to map the execution back to the original source code during debugging.
- **Diminishing Returns:** Beyond a certain point, spending more time optimizing yields very little improvement in execution speed.

**iv. What is global data flow analysis? How does it differ from local optimization?**
**Answer:**
**Global Data Flow Analysis:**
- It is the process of collecting information about the flow of data across the entire program or a whole procedure, tracking how variables are defined and used across different basic blocks.
- It involves constructing a Control Flow Graph (CFG) and solving data flow equations to understand the global state (e.g., reaching definitions, live variables).
- This analysis enables global optimizations that span multiple basic blocks.

**Differences from Local Optimization:**

| Feature | Local Optimization | Global Optimization (using Data Flow Analysis) |
| :--- | :--- | :--- |
| **Scope** | Operates strictly within a single basic block (a straight-line sequence of code without branches). | Operates across multiple basic blocks, considering the entire control flow of a function/program. |
| **Information** | Relies only on information available locally in the block. | Relies on data flow analysis to gather information across boundaries of basic blocks. |
| **Complexity** | Simple, fast, and easy to implement. | Complex, slower, requires building CFG and solving equations. |
| **Examples** | Local common subexpression elimination, local dead code elimination. | Global common subexpression elimination, loop invariant code motion, global register allocation. |

**iv. Explain the following with examples:**
**a) Common sub expression elimination**
**b) Dead Code Elimination**
**c) Loop Optimization**

**Answer:**
**a) Common Subexpression Elimination:**
This technique identifies multiple instances of the same expression being calculated with the same operands (where the operands haven't changed between evaluations) and replaces the subsequent evaluations with the previously computed result.
*Example:*
**Before:**
`x = a * b + c;`
`y = a * b + d;`
**After:**
`t = a * b;`
`x = t + c;`
`y = t + d;`

**b) Dead Code Elimination:**
This involves removing code that does not affect the program's final output. This includes code that computes values never used, or code blocks that can never be reached (unreachable code).
*Example:*
**Before:**
```c
int foo() {
    int x = 10;
    int y = 20;
    return x;
    y = 30; // Unreachable dead code
}
```
**After:**
```c
int foo() {
    int x = 10;
    return x;
}
```

**c) Loop Optimization:**
Techniques applied to loops to improve execution speed, as programs spend most of their time inside loops.
*Examples:*
1. **Code Motion (Loop Invariant Code Motion):** Moving expressions that yield the same result in every iteration outside the loop.
   *Before:* `while (i < n) { x = y + z; i++; }` (where `y` and `z` don't change).
   *After:* `t = y + z; while (i < n) { x = t; i++; }`
2. **Loop Unrolling:** Replicating the loop body to decrease the number of times the loop condition is evaluated.
   *Before:* `for(int i=0; i<4; i++) sum += a[i];`
   *After:* `sum += a[0]; sum += a[1]; sum += a[2]; sum += a[3];`
3. **Strength Reduction:** Replacing an expensive operation within a loop with a cheaper one (e.g., replacing multiplication with addition).
   *Before:* `for(int i=0; i<10; i++) y = i * 4;`
   *After:* `t = 0; for(int i=0; i<10; i++) { y = t; t = t + 4; }`
